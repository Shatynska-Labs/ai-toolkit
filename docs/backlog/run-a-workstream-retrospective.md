Archiving a workstream moves its file and nothing more, so what the work taught is kept only where a session happens to remember it. BMAD runs a retrospective at the end of each epic. Add one to the workstream's archive: compare the plan with what happened — `git log -p` on the workstream file shows every plan edit, since the file holds no progress — and the cost of the gates across its changes (review rounds, failed gates, waivers); then route each lesson to a rule, a skill, a backlog entry or a memory, or to nowhere, rather than keeping a retrospective document. A change's archive runs none, and the archived file keeps one line recording that it ran, as `complete-the-workstream-loop`'s Decisions record.
